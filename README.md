墨记是 macOS 上的 Markdown 编辑器，中文优先。我一个人写的，主要写给自己用。

我写得最多的是需求文档。一份像样的需求文档，里面得有能点的原型；写的时候，旁边得开着参考资料；写完了，改稿越来越多交给 AI。这几样东西原来散在好几个窗口里，来回切。墨记把它们收进一个窗口：

- 原型写成 `html` 块，就在正文里跑；
- 右栏开网页，或者开另一篇文档；
- 改稿意见在原文上逐条标注，攒齐了一次复制给 AI。

还有一件不显眼、但我最较真的事：中文输入。表格里打字、长段落折行处上屏，不丢字，不跳光标。

## 会跑的 html 块

![左边是 .md 文件里存的一段 html 代码块，带 script；右边是墨记打开后的样子：一张可交互的分享卡原型，右下角有缩放控制条](docs/readme/html-block.png)

在 `.md` 里写一个 `html` 代码块，墨记显示的不是源码，是它跑起来的样子。上图左边是文件里实际存的字，右边是打开以后看到的东西。需求文档里的原型、数据报告里的图表，都可以这样直接长在正文里，不用再另附一个链接。

块里带 `<script>` 也照跑。让脚本跑起来不难，难的是让它只在自己的格子里跑：

![三层隔离示意：主进程、编辑器渲染进程、html 块的 iframe。块里的脚本伸向编辑器界面、文档内容、本地文件的三条线都在 iframe 边界被拦下](docs/readme/sandbox.png)

- html 块整块放进 `sandbox="allow-scripts"` 的 iframe。脚本拿不到编辑器界面和文档内容，也碰不到本地文件。
- 再往外一层，编辑器自己的渲染进程也开着 `sandbox: true` 和 `contextIsolation`。要用 Node 能力，只能走 `contextBridge` 的白名单。

用起来还有这些：

- 右下角控制条，50%–200% 缩放，拖角改视口大小。预览高度跟着内容走，在 60–1200px 之间。
- 调好的尺寸和缩放比例随文档存下，下次打开还是那样。
- HTML 和脚本就写在 `.md` 里。一个文件发出去，对方离线打开照样渲染。
- 手里已经有一个 `.html` 文件，直接粘进来。会弹个气泡让你选：「内嵌到文档」把同目录的样式、脚本、图片一起内联，转成单个 `.md`；「上传图床并插入链接」走你配好的上传服务，文档里只留一条链接。
- 导出 HTML 时，块还是活的沙箱帧：能点、能切页签，右下角工具条照样缩放和拖拽。导出 PDF 或 Word 时，它定格成一张等比截图，和屏幕上看到的一致。

## 改稿意见，逐条交给 AI

让 AI 改文章，难的往往不是改，是说清楚改哪儿。「第三章那段」「上面那个数」，它常常改错地方。

![编辑器里三处文字带淡墨蓝高亮和序号，标注卡片上有「删掉」等常用语；右栏标注面板列出三条意见，底部是「复制所有标注」按钮](docs/readme/annotate.png)

选中一段话，工具条上点「标注」，写一句意见。正文只留一道淡墨蓝高亮和一个序号，右栏「标注」面板列着每一条。

反复要说的话，比如「看不懂，优化表达」「删掉」，可以存成常用语。选中文字，点一下，就标好了。

一轮攒齐，点「复制所有标注」：

![左边是复制出来的结构化文本，按章节路径与行号、原文引用、所在段落、修改要求分段；右边是 AI 改完后的标注面板，前两条显示「内容已变化」，第三条「未变化」](docs/readme/handoff.png)

复制出来的是一段结构化文本：章节路径、行号、原文引用、所在段落、你的要求。整段粘给 AI Agent，每一条改哪儿，它不用猜。

复制过的条目标「已复制」。AI 改完文档，墨记自动比对原文，逐条提示「内容已变化」还是「未变化」。漏改的一眼就能看出来。核对完，归档进历史。

批注存在应用数据目录里，不往 `.md` 里写一个字。我不喜欢批注混进原文，交出去的文档应该是干净的。

## 右栏：一个小浏览器，或者另一篇文档

![左边写需求文档，右栏网页模式开着一篇参考文章，右侧竖排三个网页标签，底部是地址栏；一个被拖起的标签正往右栏里放](docs/readme/side-panel.png)

右侧面板有「网页」「文档」两种模式，一键切换。

网页模式有自己的标签页和地址栏，几个页面来回切，能前进后退。⌘+ / ⌘- / ⌘0 缩放，0.25 到 3 倍，也可以直接「适应宽度」。查资料不用离开这个窗口。

文档模式放另一篇 Markdown。把标签页拖进右栏，两篇并排，各改各的。滚动条放在中间的分隔带上，不压正文。

## 中文输入

![上方是输入法的三步：拼音停在输入法里、选字、上屏。下方两个场景：表格单元格里正在输入拼音并弹出候选框；软换行的长段落里，折行处正在输入拼音](docs/readme/ime.png)

中文不是按一个键出一个字。拼音先停在输入法里，选定了才上屏。编辑器要是在上屏那一下重绘，字就可能丢，光标就可能跳。

墨记修过两处：

- 表格单元格里的输入法输入，整条链路过了一遍；
- 软换行的长段落里，输入法提交的内容完整保留。

结果是写中文不丢字，不跳光标。这类毛病常被算到输入法头上，其实是编辑器没接住。

界面内置十余种语言，中文排第一。中文界面是重新趟过的，不是套一份翻译了事。

## 安装

从 [Releases](https://github.com/lixiaoshuang79/momark/releases/latest) 下载 dmg 或 zip。打开 dmg，把「墨记」拖进「应用程序」。

安装包以 arm64（Apple 芯片）为主。Intel 机器可以自己构建 x64 版，见[从源码构建](#从源码构建)。

### 第一次打开被 macOS 拦下

墨记没做 Apple 公证签名。第一次打开会弹窗：「Apple 无法验证“墨记”是否包含可能危害 Mac 安全或泄漏隐私的恶意软件」。这样放行：

1. 打开「系统设置 → 隐私与安全性」，在「安全性」一栏点「仍要打开」；
2. 再打开一次墨记，在弹窗里选「打开」。

macOS 15 起，老办法「右键 → 打开」已经失效，不用再试。

如果提示的是「已损坏，无法打开」，在终端执行：

```bash
xattr -cr /Applications/墨记.app
```

## 从源码构建

需要 Node.js ≥ 20.19（推荐 22）、pnpm ≥ 10。

```bash
pnpm install
pnpm build:mac          # 默认 arm64；Intel 用 pnpm build:mac:x64
```

产物：

- 应用：`dist/mac-arm64/墨记.app`
- 安装包：`dist/momark-mac-arm64-1.5.6.dmg`、`dist/momark-mac-arm64-1.5.6.zip`

开发用 `pnpm dev`，渲染进程跑在 `localhost:9333`。

## 技术栈与仓库结构

Electron 42 · Vue 3.5 · TypeScript（strict）· Pinia · electron-vite 5 · electron-builder 26，用 pnpm monorepo 组织。

编辑内核是块级文档模型：marked 解析 Markdown，ot-json1 + ot-text-unicode 做增量更新，snabbdom 渲染视图，rxjs 管事件流。

| 目录               | 说明                                 |
| ------------------ | ------------------------------------ |
| `packages/desktop` | 桌面端（Electron 主进程 + 渲染进程） |
| `packages/muya`    | 块级编辑内核（TypeScript）           |
| `packages/muyajs`  | 旧编辑内核，退役中                   |
| `packages/website` | 官网 / 文档站                        |
| `docs/`            | 开发文档                             |
